# Configuration Architecture Update

## Summary of Changes

We've simplified the application's configuration approach to address the complexity of having configuration settings spread across multiple files. The new approach centralizes all configuration in a single location and uses environment variables for all settings.

### What Changed

1. **Eliminated Multiple Config Files**: 
   - Removed the need for multiple JSON configuration files
   - Consolidated all configuration into the `.env` file or environment variables

2. **Created a Central Config Service**:
   - Added a new `configService.js` utility module that loads and provides access to all configuration
   - Handles environment-specific settings (development, production, test) automatically

3. **Simplified Authentication Handling**:
   - Development environment: Uses username/password from .env file
   - Production environment: Uses Azure Managed Identity automatically
   - No need to modify code for different environments

4. **Improved Documentation**:
   - Updated README.md with detailed configuration instructions
   - Added .env.example template file

### Benefits

1. **Simplified Onboarding**: New team members can understand the configuration in one place
2. **Easier Deployment**: No need to manage multiple config files for different environments
3. **Better Security**: Sensitive information is not stored in configuration files
4. **CI/CD Friendly**: Environment variables make it easier to integrate with CI/CD pipelines
5. **Follows Azure Best Practices**: Uses Managed Identity in production

### How to Use the New Configuration

1. **Local Development**:
   - Copy `.env.example` to `.env` and fill in your values
   - All environment-specific logic is handled automatically

2. **Production Deployment**:
   - Set App Service Configuration settings with the same names as in `.env`
   - Managed Identity will be used automatically for Azure resources

3. **Accessing Configuration in Code**:
   ```javascript
   const configService = require('../utils/configService');
   
   // Get a configuration value
   const storageAccount = configService.get('azure.storage.accountName');
   
   // Use environment helpers
   if (configService.isProduction()) {
     // Production-specific code
   }
   ```

## Migration Steps

The code has been migrated to the new approach. For existing developers, please note:

1. The following folders and files have been **removed**:
   - `/config` directory with all JSON files
   - `/src/config` directory with all JSON files
   - These are no longer needed as all configuration is now in `.env`

2. The `config` npm package has been **uninstalled** as it's no longer required

New developers can simply:
1. Clone the repository
2. Copy `.env.example` to `.env` and fill in their values
3. Run `npm install` and `npm run dev`
